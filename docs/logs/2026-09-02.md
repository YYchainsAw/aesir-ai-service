# Aesir AI Service｜开发记录

> 日期：2026-09-02  
> 开发成员：**yjx**、**dyh**  
> 项目：Aesir Combat Prototype 的 AI 队友模型服务

## 本阶段目标

在 UE5 尚未完成队友与 Boss 战斗系统前，先完成可独立验证的 Python 服务层：

```text
非战斗：文本/语音转写 → Alice 人设对话 → 文本与表现 ID
战斗：文本/语音转写 → 战术解析 → TacticalOrder JSON
```

UE 将来只负责调用服务、验证结果并播放动画/执行技能；Python 不直接操控游戏世界。

## 已完成

### 共用基础

- FastAPI 服务、`/health` 健康检查、Pydantic Schema 与 Pytest 测试。
- 通用 OpenAI 兼容 `LLMClient`，通过 `.env` 配置模型地址、模型名、密钥和超时。
- LLM JSON 结果使用 Pydantic 严格校验，未知字段或非法 ID 不会交给 UE。
- 支持 SOCKS 代理依赖，避免本地代理配置导致 HTTP 客户端初始化失败。

### 非战斗陪伴聊天

- `POST /v1/companion/chat` 已可用。
- `data/companions/primary_companion.yaml` 是 Alice 的唯一静态人设来源。
- 人设：Alice（别名：艾莉），活泼开朗、略带傲娇、对玩家暗藏情愫，但尊重玩家边界。
- YAML 定义对话规则、允许的情绪 ID、动作 ID、表情 ID、默认表现与战斗确认台词。
- 支持 `mock` 与 `llm` 两种聊天后端；LLM 故障时回退 YAML 默认回复。
- 未登记的 `companion_id` 会被拒绝，避免错误角色使用 Alice 的人设回复。
- 已完成一次真实 LLM 聊天接口联调，响应 `source: "llm"` 且返回合法表现 ID。

### 战术解析原型

- 现有 `/parse-command` 支持五类原型指令：
  - 条件施法；
  - 保留技能；
  - 优先普攻；
  - 跟随并保持距离；
  - 撤退保命。
- 战术响应包含可观察来源：
  - `source: "llm"`：模型成功解析；
  - `source: "rule"`：直接规则解析；
  - `source: "rule_fallback"`：LLM 不可用或结构不合法后回退规则。
- 战术响应包含 `companion_reply`；短回复和情绪 ID 从 Alice YAML 的 `tactical_acknowledgements` 读取。
- 当前战术 Schema 仍使用 `Eirin / Boss / Explosion` 作为临时固定占位，尚未与 Alice 稳定 ID 统一。

## dyh 后续任务

### P1：能力目录驱动的战术协议

目标：将当前写死的 `Eirin / Boss / Explosion` 原型替换为 UE 可动态传入的能力目录。

新增目标接口：

```text
POST /v1/commands/parse
```

请求示例：

```json
{
  "protocol_version": "0.1",
  "request_id": "uuid",
  "text": "Alice，等 Boss 眩晕后使用爆裂魔法。",
  "context": {
    "agents": [
      {
        "id": "companion.alice",
        "ability_ids": [
          "ability.alice.explosion",
          "ability.alice.heal"
        ]
      }
    ],
    "target_selectors": [
      "encounter.primary_hostile",
      "party.player"
    ],
    "state_tags": [
      "state.stunned",
      "state.phase_two"
    ]
  }
}
```

建议新增目录：

```text
app/
├─ schemas/
│  ├─ tactical_context.py
│  └─ tactical_order_v1.py
└─ api/v1/
   └─ tactical.py

tests/
├─ fixtures/
│  └─ tactical_commands_zh.json
└─ test_tactical_v1.py
```

验收标准：

- 角色、技能、目标和状态均来自请求 `context`，未登记 ID 一律拒绝；
- 结果保留 `source: llm/rule/rule_fallback`；
- 至少 30 条中文有效/无效战术指令测试；
- 保留旧 `/parse-command` 作为兼容调试入口；
- 不依赖 UE 已完成角色、动画或关卡。

### P2：ASR Adapter 骨架

目标接口：

```text
POST /v1/speech/transcribe
```

职责：上传 WAV/PCM 音频，验证格式、时长与大小，再由 `MockTranscriber` 或真实 ASR Adapter 返回转写文字。

要求：

- 先实现 MockTranscriber 与本地 WAV 测试，不等待 UE 麦克风接入；
- 预留 `faster-whisper` Adapter；
- ASR 只负责音频转文字，不负责聊天或战术意图；
- 返回 `request_id`、`text`、`language` 和明确错误信息。
