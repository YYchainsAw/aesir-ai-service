## 全项目可行性与完整性审查（同日）

静态审查（代码/文档双线）+ 运行时冒烟（全部端点、5 指令、错误分支、LLM 真实调用）。
结论：**整体可行，无致命问题**；发现并修复：

### 已修复

1. **LLM 越界静默替换（中高）**：指令提到的技能不在能力目录时，LLM 会用目录内
   其他技能替代而非拒绝。已在 prompt 增加「必须返回 recognized:false，不得替代」，
   实测修复（越界 → recognized:false + rule_fallback）。
2. **LLM prompt golden 示例硬编码 alice（高）**：改为从本次请求目录动态取
   agent/ability/selector/state 生成示例；非 alice 目录（如 bob）实测可用。
3. **契约金标准缺字段（中）**：`UE5-协议格式契约-v0.1.md` §2 补 `source` 与
   `companion_reply` 字段及说明。
4. **文档口径（低-中）**：LLM 指南超时 30→15 对齐代码；联调规范「尚未开始」
   列表删除已实现项；README/规范测试数 44→50；项目介绍接口表补 transcribe、
   修正「扁平信封」表述；`.env.example` 示例旧名艾琳→艾莉。

### 已知未修（记录在案）

- 规则解析器多意图冲突顺序（retreat priority 90 但判断序在 hold 之后）：v0.1
  golden 输入无冲突，留待 v0.2 一并处理。
- order 内部模型未设 `extra="forbid"`（顶层有）：Pydantic 默认忽略多余字段，
  与严格校验理念有差距，风险低。
- companion YAML 损坏时 API 返回 500（未捕获 CompanionProfileError）：部署
  时配置缺失才会触发，风险低。
- voice/speech multipart 字段名不同（`file` vs `audio`）：契约如此规定，UE 文档
  已注明。
- LLM_TIMEOUT_SECONDS=15s 大于 UE 3s 预算：服务端超时>客户端超时是常见模式，
  不改；如需收紧可 `.env` 调低。

### 可行性结论

- faster-whisper small + 8GB 显存 + int8_float16 + 一句 ~0.5s：可行且保守。
- UE 3s 端到端预算：规则+mock <0.1s；真实 ASR+规则 ~0.6s；真实 ASR+LLM
  1.1~1.9s——均在预算内，LLM 网络抖动由规则回退兜底。
