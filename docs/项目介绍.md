# Aesir AI Service — 项目介绍

## 1. 项目概述

**Aesir AI Service** 是为 **Aesir Combat Prototype**（UE 战斗原型）提供本地 AI 能力的后端服务。

核心职责：把来自**文本或语音**的玩家战术指令，转换为 UE 可以校验并执行的 **`TacticalOrder` JSON**。服务在本地运行，无外部依赖，UE 客户端通过 HTTP 直接调用。

## 2. 背景与目标

在战斗原型中，玩家需要指挥 AI 队友「艾莉（Alice）」执行战术动作。原始需求是支持语音/文本输入，但直接让 LLM 生成 UE 命令存在**不可控风险**（幻觉技能、非法参数、越权指令等）。

因此本项目采用「**受限协议 + 可替换解析器**」的设计：

- **协议层**：`TacticalOrder` 的每个字段都限定在严格白名单内（`intent`、`ability_id`、`target`、`state` 均为 `Literal` 枚举；`order` 的各字段又由请求 `context` 里的能力目录给出），UE 端在 C++ 侧做 1:1 结构映射并二次校验。
- **解析层**：当前是可替换的规则 / LLM 解析器（`command_parser.py` 做后端选择与回退），**语音识别结果也复用同一解析层**。无论输入来源是文本还是 ASR 文本，输出协议都不变。

这样即使接入 LLM 或语音，UE 通信协议与校验逻辑也保持不变，把风险收敛在解析层。

## 5. 核心设计

### 5.1 协议：`TacticalOrder`（契约 v0.1）

`TacticalOrder` 由 `intent` 字段判别的联合类型；每个意图内部的 `when` / `then` / `expires` 又各自按 `type` 判别（详见 `docs/UE5-协议格式契约-v0.1.md`）：

| 意图 `intent` | 触发 `when` | 动作 `then.type` | 示例指令 |
| --- | --- | --- | --- |
| `conditional_cast` | `state_entered`(subject, tag) | `cast_ability` | 艾莉，等 Boss 眩晕时使用爆裂魔法 |
| `hold_ability` | — | `hold_ability` | 艾莉，保留爆裂魔法 |
| `prioritize_attack` | — | `set_priority` | 艾莉，优先普通攻击 |
| `follow_keep_distance` | — | `follow` | 艾莉，跟随我并保持距离 |
| `retreat` | — | `retreat` | 艾莉，撤退并优先保命 |

响应信封字段（`extra=forbid`，方便 UE C++ 结构 1:1 映射；`order` 内每种 intent 的订单共享 `order_id`/`agent_id`/`priority`/`expires` 基础字段）：

```json
{
  "protocol_version": "0.1",
  "request_id": "<uuid 回显，缺省服务端生成>",
  "recognized": true,
  "message": "知道了，先撤，优先保命。",
  "source": "rule | llm | rule_fallback",
  "order_id": "<uuid>",
  "agent_id": "companion.alice",
  "priority": 90,
  "expires": { "type": "encounter_end" },
  "companion_reply": { "reply_text": "...", "emotion_id": "..." }
}
```

各 `when.subject` / `then.ability_id` / `then.target` 必须来自请求 `context` 的能力目录白名单，杜绝显示名 / 硬编码出协议。

### 5.2 解析流程

```
玩家文本 / ASR 文本 → 后端选型（rule / llm）
        → 规则解析器 _normalize（去空格/标点/大小写/全半角）
        → 匹配 agent → 按「更具体优先」匹配 5 个意图
        → 生成 TacticalOrder / recognized=false
        → LLM 失败时回退到规则（rule_fallback → source 标记）
```

未识别的指令**明确返回** `recognized: false` 且 `order: null`，而不是猜测或抛错，保证 UE 端可以安全地忽略未知输入。

### 5.3 可替换性

解析逻辑隔离在 `app/services/command_parser.py`，输出 `ParseCommandResponse` 由 schema 固定。接入 LLM 或语音识别时只替换解析器后端 / ASR 后端，不改动路由、schema 和 UE 协议。`source` 字段标注最终实际来源（`rule` / `llm` / `rule_fallback`），供 UE 端日志与降级观测。

### 5.4 语音转写（可插拔 ASR）

`/v1/voice/command` 接收 WAV / 16kHz / 单声道 / 16bit 的 multipart 音频，先经 ASR 转成文本，再送入与文本端**同一** `parse_command` 解析层，直接复用契约 v0.1。

- 后端由 `AESIR_ASR_BACKEND` 决定：`mock`（返回 `AESIR_ASR_MOCK_TEXT`，自测/回退用）/ `faster_whisper`（真实本机 Whisper，默认 `small` 模型；模型/设备/量化/语言可配）。
- 转写出空串 → `recognized: false`；转写抛错 → `502`。

## 6. 当前接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/health` | 健康检查，返回 `protocol_version` |
| `POST` | `/parse-command` | **遗留别名**：只传 `text`，服务端回填默认能力目录。正式联调请用 v1 |
| `POST` | `/v1/commands/parse` | 契约 v0.1：携带 `text` + `context`（能力目录）+ `request_id` |
| `POST` | `/v1/voice/command` | 语音：multipart `file`(WAV) + 可选 `request_id`/`context_json` |
| `POST` | `/v1/tactical/resolve` | v0.2：语义意图 + 战斗快照 → 上下文战术决策（规则策略） |
| `POST` | `/v1/speech/transcribe` | 独立转写：只做音频 → 文本，与组合端点并存 |
| `POST` | `/v1/companion/chat` | 非战斗陪伴对话（mock / llm 后端，人设见 `data/companions/`） |

交互式文档：`http://127.0.0.1:8000/docs`（FastAPI 自动生成）。
