# Aesir AI Service — 项目介绍

## 1. 项目概述

**Aesir AI Service** 是为 **Aesir Combat Prototype**（UE 战斗原型）提供本地 AI 能力的后端服务。

第一阶段的核心职责：把玩家输入的**文本战术指令**转换为 UE 可以校验并执行的 **`TacticalOrder` JSON**。服务在本地运行、无外部依赖，UE 客户端通过 HTTP 直接调用。

## 2. 背景与目标

在战斗原型中，玩家需要指挥 AI 队友「艾琳（Eirin）」执行战术动作。原始需求是支持语音/文本输入，但直接让 LLM 生成 UE 命令存在**不可控风险**（幻觉技能、非法参数、越权指令等）。

因此本项目采用「**受限协议 + 可替换解析器**」的设计：

- **协议层**：`TacticalOrder` 的每个字段都限定在严格白名单内（如 `intent`、`ability_id`、`target`、`state` 均为 `Literal` 枚举），UE 端在 C++ 侧做 1:1 结构映射并二次校验。
- **解析层**：当前是确定性规则解析器（`command_parser.py`），后续可**整体替换**为 LLM 适配器或语音识别结果，而**不改变输出协议**。

这样即使未来接入 LLM，UE 通信协议与校验逻辑也保持不变，把风险收敛在解析层。

## 5. 核心设计

### 5.1 协议：`TacticalOrder`

`TacticalOrder` 是一个由 `intent` 字段判别的联合类型（discriminated union），每种意图只暴露与其相关的触发/动作字段：

| 意图 `intent` | 触发条件 `trigger` | 动作 `action` | 示例指令 |
| --- | --- | --- | --- |
| `conditional_cast` | `Boss.Stunned` | `CastAbility(Explosion)` | 艾琳，等 Boss 眩晕时使用爆裂魔法 |
| `hold_ability` | — | `HoldAbility(Explosion)` | 艾琳，保留爆裂魔法 |
| `prioritize_attack` | — | `Attack` | 艾琳，优先普通攻击 |
| `follow_keep_distance` | — | `Follow(Player, keep_distance)` | 艾琳，跟随我并保持距离 |
| `retreat` | — | `Retreat` | 艾琳，撤退并优先保命 |

所有订单共享一个扁平的信封字段（便于 UE C++ 结构 1:1 映射）：

```json
{
  "protocol_version": "1.0",
  "agent": "Eirin",
  "priority": "high",
  "expires_on": "EncounterEnd"
}
```

### 5.2 解析流程

```
玩家文本 → _normalize（去空格/标点/大小写/全半角）
        → 匹配 agent（艾琳/Eirin）
        → 按「更具体优先」的顺序匹配 5 个意图
        → 生成 TacticalOrder / 返回 recognized=false
```

未识别的指令会**明确返回** `recognized: false` 且 `order: null`，而不是猜测或抛错，保证 UE 端可以安全地忽略未知输入。

### 5.3 可替换性

解析逻辑完全隔离在 `app/services/command_parser.py`，输出类型 `ParseCommandResponse` 由 schema 固定。未来接入 LLM / 语音识别时，只需替换该模块，不改动路由、schema 和 UE 协议。

## 6. 当前接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/health` | 健康检查，UE 用于确认本地服务可用 |
| `POST` | `/parse-command` | 将文本指令解析为 `TacticalOrder` |

交互式文档：`http://127.0.0.1:8000/docs`（FastAPI 自动生成）。
