# 0 项目章程与范围背景

## 0.1 延续的七项原则

这些原则提取自原 v1.0，不新增数据库、审批平台或运维流程。与其相关的规则和验收仍需在下文按编号说明。

| 原编号 | 当前原则与理由 |
| --- | --- |
| I 配置外置 | 人格、能力目录、阈值、优先级、节流、关系规则与表现 ID 使用版本化 YAML/JSON。配置非法应给出可定位错误；调参不把台词/业务数值散入代码。实际配置版本随响应与记录可追溯。 |
| II 模型输出不可信 | 外部输入隔离；输出依次进行结构、上下文白名单、人设一致性检查。失败按受控路径重试/降级/拒绝；不得因为“模型说可以”绕过规则。严格结构检查是目标，当前不同入口的覆盖差距见第 5 部分。 |
| III UE 唯一权威 | UE 裁定血量、命中、位移、资源、冷却、目标和动画；Python 返回候选建议。快照可能过期，执行前由 UE 再校验，服务的只读工具不能改变世界。 |
| IV 测试先行 | 新行为实现前准备有意义的失败/正常/条件不满足/重复事件用例；契约和 golden 样例先于相关实现变更。默认测试隔离外部后端，缺依赖的跳过需明确范围。此原则不要求为本次可逆文档编辑新增镜像测试。 |
| V 可解释、可回退 | 原因、来源、版本和关联标识用于解释决策；任一依赖故障时给出明确降级/拒绝，客户端保留本地兜底，不阻塞游戏主流程。启动时非法配置可以快速失败，不能假装带坏配置正常工作。 |
| VI 单一指令寻址 | 统一指令信封，按动作类型分发；实现按域分文件，不再新建平行命令族。现有 v0.1/v0.2 兼容入口的存在不等于已经完成统一信封到旧 order 的全部映射。 |
| VII 简单优先 | 无明确必要性不引入 DB/MQ/向量库或投机抽象。先完成可演示、可解释、可验收的主线，扩展不成为当前闭环前置。 |

本机回环部署、本地文件持久化、凭据不入代码/日志/响应、外部输入隔离、人格表达不越玩家边界继续有效。真实 LLM/ASR 可选；离线规则模式可以工作不等于真实模型模式没有外发。原“仅保留摘要”与现有记录的差距在 NFR-05 和第 5 部分明列。

## 0.2 整组体验、责任与演进边界

玩家在 UE 的 ARPG 中与 Alice 协作：同一句请求应随战况、同伴状态与关系产生合法且可解释的结果。治疗/护盾等是体验示例，不表示 UE 已有这些技能；能下发什么以当场获准目录和实际能力为准。服务侧对话、记忆、关系、自主建议可分别验收，完整游戏闭环还需要 UE 校验、执行和真实反馈。

| 责任方 | 负责内容 | 不能代替的责任 |
| --- | --- | --- |
| dyh（Python NPC） | 服务 schema/路由、LLM/ASR接入、人格、记忆/关系、自主行为、策略与服务测试 | 不能证明 UE 已施法、命中、恢复或显示了结果 |
| yjx / YYchainsAw（UE 与 Boss RL） | UE 战斗、行为树/组件、HTTP、UI/动画，以及独立 Boss RL 训练与冻结推理 | 不把另一仓需求目标视为服务负责人已完成协议接受 |
| 共同 | 能力/事件/表现 ID、上下文与回执映射、golden 样例、试玩规则和联调判据 | 两端各自通过测试不等于端到端通过 |

沿用总策划的边界：一进程一游戏，按游戏/角色配置组织数据；L0 提供对话/记忆/关系，L3 启用完整世界/事件/战术链路，能力不足必须明确门控或降级。人格包引用须落在所属游戏声明中；格式细则只在 schema 维护。跨游戏复用属于已开展的架构演进，不把全部第三方接入或行为级门控自动加入当前课程交付。单独人格微服务、动态 Scene 枚举、单进程多游戏 profile、通用方言映射引擎均不作为本轮任务。

NPC 走位 RL、对话 RL 导演层等扩展仍须独立确认；Boss RL 是本仓独立模块与 UE 研究线，不并入以下 8 REQ。M1/M2 主线或当前单关的验收不以这些扩展成功为前置。旧策划的阶段勾选、工期估计和已经过期的下一步列表不再复制，任务统一在 todo/Issue 更新。

# 第三部分 对象职责与局部协作

## 3.1 候选筛选

以下为分析概念，不要求新增同名Python类。当前统一Envelope/类型联合不等于五种有独立身份的实体；关系和职责也不由代码类名数量决定。

| 候选 | 处理与职责依据 |
| --- | --- |
| CompanionProfile | 保留角色身份/人格配置概念；按游戏和companion_id选择，核心设定受保护；REQ-01/08、BR-08/10 |
| MemoryEntry / MemoryArchive | 保留有来源/时间的记忆条目与分层档案职责；配置/会话/档案区别清楚；REQ-01/07、BR-05 |
| SessionMemory | 局部保留角色会话分区的管理职责；跨会话持久记忆不能因省略session_id就称全部无状态 |
| RelationshipState | 保留关系状态和事件驱动规则；清记忆不清关系；REQ-01/02/05、BR-04 |
| WorldSnapshot / WorldEvent | 保留只读值/事件输入，快照不是权威世界；事件键用于有限缓存，不能代替执行去重；BR-01/03 |
| Directive | 保留统一建议值，携带上下文关联、类型/目标、优先级/有效期和理由；类型按战斗/移动/交互/社交/日常分类，不为本轮建立平行协议 |
| AbilitySpec | 保留获准能力目录项；一般指令可零引用，需能力时必须授权，数量未冻结；BR-01 |
| ExecutionReceipt | 保留客户端报告的事实值；关联order_id/encounter_id/request_id，directive_id映射仍待对齐；当前服务追加记录，不自动维护完整执行实体状态机 |
| ActivityDomain | 枚举/分类值，不造独立有身份实体 |
| MemoryResetCoordinator / 重置接口 | 局部control/boundary职责，可映射现有reset_memory函数/HTTP路由；协调不吞并人格/关系/记忆的业务约束 |
| DialogueService、Arbiter、Throttle、StyleGuard | 应用/控制职责，移出领域概念图不是删除其实现，也不表示控制版型不得存在 |
| System、Database、“配置” | 不作装饰性领域实体；具体持久化与外部边界按协作用例解释 |

## 3.2 核心CRC与不变量

每项职责可独立解释；不要求用getter/setter凑方法。内聚的数据/规则可由一个实现对象承担，协调者不能随意改写全部实体状态。

| 对象 | 两项业务职责 | 协作者 | 不变量（及依据） |
| --- | --- | --- | --- |
| CompanionProfile | 维护游戏/角色身份及人格版本；提供受保护的禁忌/表现配置并拒绝越权改写 | MemoryArchive、RelationshipState、角色注册表 | 当前请求只关联已登记且属于当前游戏的角色；memory/reset不改变人格（BR-08/10） |
| MemoryEntry / MemoryArchive | 维护内容的来源/时间及层级；按预算和保留优先级检索/清理指定角色记录 | CompanionProfile、SessionMemory | 不将推测存为事实，不读取/清除其他角色条目；具体容量随加载配置（BR-05/08） |
| SessionMemory | 维护指定角色的会话分区；清理匹配分区并报告实际数量 | CompanionProfile、重置协调 | 仅清指定角色分区；cleared_sessions不冒充长期清理成功（BR-05/08） |
| RelationshipState | 依据有效事件/信号更新；保护阶段、冷却和正向日上限 | CompanionProfile、WorldEvent、对话信号 | 关系值保持0～100，阶段与值一致，清记忆不将关系重置（BR-04） |
| Directive | 表达当前快照内的受限建议；携带合法性所需标识、有效期/理由供UE复核 | WorldSnapshot、AbilitySpec、ExecutionReceipt | 不引用上下文外目标/能力，需技能时必须获准；数量未冻结（BR-01） |
| WorldEvent | 表达有来源的状态边沿事实；提供作用域内幂等关联键 | RelationshipState、事件处理控制 | 同一有效缓存键回放不产生新服务反应，缓存外保证不夸大（BR-03） |
| ExecutionReceipt | 表达客户端实际报告的结果和原因；关联原order/请求/遭遇供检查 | Directive、客户端、追加存储 | 不把accepted/HTTP202或缺记录推断为完成；不声称日志追加就是去重/终态合并（NFR-04） |

## 3.3 分析类图与关系理由

![NPC领域对象](../design/uml/png/12a-npc-service-domain.drawio.png)

| 关系 | 双向读法、理由与反例 |
| --- | --- |
| CompanionProfile—MemoryEntry | 当前角色可有0..*记忆；每条记忆归属于一个游戏/角色。用普通关联说明归属，不用“清记忆”推导人格生命周期。反例：A和B共享同一可变记忆条目而造成串读/串清，违反BR-08。 |
| CompanionProfile—RelationshipState | 本地单玩家范围中，一个角色至多0..1当前关系状态；关系只归该角色/当前玩家作用域。尚未建立/损坏恢复是边界例，不强制启动时永远已有1条。反例：memory/reset重建人格/关系，违背该操作范围。 |
| Directive—AbilitySpec | 一般指令0..*能力引用，每个能力可被多条建议引用；条件是需技能的建议必须引用获准能力、数量未冻结。合法反例是无技能observe；非法反例是cast引用不存在能力。普通关联的数量不替代条件谓词。 |
| Directive ⇢ WorldSnapshot / WorldEvent | 指令依赖只读快照提供合法标识依据，依赖事件提供可追溯触发事实。每次心跳至多1条建议或无动作，事件可返回反应与可选动作；依赖不代表指令拥有或改变输入。 |
| ExecutionReceipt ⇢ Directive | 事实追踪依赖表达“反馈必须能找到原建议/旧order”，不是普通结构拥有关系；当前以order_id/encounter_id/request_id为主，directive_id映射/乱序语义待对齐。没有回执是合法缺信息，不能画成每个指令必已有完成回执。 |

组合如有真实整体/部分生命周期可使用，但本模型不靠清记忆操作推断关系销毁。活动类型是分类；同一Envelope如何在代码判别，继续以schema为准。

[UML-14图源](../design/uml/src/14-memory-reset-sequence.drawio)

![记忆重置协作](../design/uml/png/14-memory-reset-sequence.drawio.png)

成功消息：①调用方→重置接口→协调：请求指定角色；②协调→注册表：确认身份/范围；③协调→SessionMemory：清角色会话并收取数量；④协调→MemoryArchive：清角色长期记忆并收到完成；⑤协调→接口→调用方：reset=true和实际cleared_sessions。没有清人格、清关系或清独立日志消息。

## 3.6 指令协作与当前回执边界

[UML-15图源](../design/uml/src/15-directive-execution-sequence.drawio)

![建议与实际回执](../design/uml/png/15-directive-execution-sequence.drawio.png)

建议产生、UE受理、本地激活/开始、命中、完成是不同事实。当前回执枚举是`accepted/executed/rejected/expired/cancelled`，协议字段和状态含义见权威契约；不新增started/hit/completed字段并宣称现已支持。HTTP202仅确认接收记录，当前存储只是JSONL追加，未校验同一指令的去重、阶段转换或乱序终态合并。

需要的目标约束是：UE拒绝过期/旧遭遇/非法动作；实际反馈可关联原建议；重复/乱序不得制造新的实际动作或虚假终态。这些约束需协议与实现另行对齐。只写`directive_id`、`order_id`或sequence字段不等于映射/状态机已经完成。LLM失败回退与合法无动作可继续交互，不能把它们都当UE执行失败。

# 附录A 原FR-001～045正文

逐条保留原v1.0文字以维持编号/来源。下列是需求正文，不是已经实现或通过的清单；与经记录修订冲突时，按本稿BR/UC的明确说明理解。FR-014的驱动来源已由2026-09-22决定扩为“事实事件＋对话情感信号”（BR-04）；FR-007补印象层（BR-05）；FR-025/030/040不强迫日常行为必选技能，但所有指令的角色、目标、行为类型等标识仍须合法，需技能时能力也须获准；FR-010不清人格/关系/独立日志，不承诺整体回滚。

- **FR-001**: 系统 MUST 以单一配置源定义每个 NPC 的人格（身份、背景、价值观、好恶、说话风格、禁忌表达、语气示例），且人格文案不得散落在代码逻辑中。

- **FR-002**: 系统 MUST 保证 NPC 的表达在其人格设定范围内，且**禁止**出现游戏机制、系统、协议等破坏沉浸感的术语。

- **FR-003**: 系统 MUST 对所有 NPC 输出执行内容校验，拒绝符合禁忌表达清单的内容；校验失败时 MUST 重试并以角色化表达兜底。

- **FR-004**: 系统 MUST 支持NPC 的持续情绪状态与当前关注点，使其跨多次交互保持情绪连贯（而非每次重置）。

- **FR-005**: NPC 人格中的核心设定 MUST 不可被模型输出或玩家输入改写。

- **FR-006**: 系统 MUST 持久化 NPC 的记忆，使其在重启后仍然有效。

- **FR-007**: 系统 MUST 分级管理记忆：当前会话内的短期上下文、跨会话的经历摘要、长期关系与事实档案，并明确各自的容量与淘汰规则。

- **FR-008**: 系统 MUST 在记忆达到容量上限时按重要性与时间淘汰，且承诺类与重大事件类记忆 MUST 优先保留。

- **FR-009**: 系统 MUST 在生成回应时按可控预算使用记忆，避免上下文无限增长。

- **FR-010**: 系统 MUST 提供清空指定 NPC 记忆的能力。

- **FR-011**: 记忆不可用时，系统 MUST 继续提供服务并降级为无长期记忆的行为，且 MUST NOT 因此中断玩家流程。

- **FR-012**: 系统 MUST NOT 将推测内容作为事实写入长期记忆，且记忆条目 MUST 可追溯来源与发生时间。

- **FR-013**: 系统 MUST 为每个 NPC 维护对玩家的长期关系状态，并持久化。

- **FR-014**: 关系变化 MUST 由游戏内发生的**事实事件**驱动，且事件类型与影响幅度 MUST 可配置。

- **FR-015**: 系统 MUST 对同类事件的重复触发实施限制，防止通过重复行为快速刷高关系。

- **FR-016**: 关系状态 MUST 划分阶段，且每个阶段 MUST 定义可观察的差异，至少覆盖：称呼与语气、主动互动频率、资源投入意愿、对危险指令的服从度。

- **FR-017**: 关系 MUST NOT 导致违反安全与合规约束的行为，也 MUST NOT 使 NPC 越过玩家边界或出现控制性表达。

- **FR-018**: 关系状态异常时，系统 MUST 以初始状态继续运行。

- **FR-019**: 系统 MUST 区分 NPC 所处的活动场景（战斗、探索、营地休整、对话、待机），并在不同场景下提供不同的可执行行为集合。

- **FR-020**: 系统 MUST 支持 NPC 在非战斗场景中的自主行为，且自主行为类型 MUST 覆盖不少于 8 类（含跟随、移动、观察、查看、交互、拾取、休整、等待、表达、自言自语等）。

- **FR-021**: 系统 MUST 在无玩家指令时，基于客户端上报的世界状态与世界时间判断是否发起自主行为；系统 MUST NOT 主动向客户端推送。

- **FR-022**: 系统 MUST 对自主行为实施节流与去重，保证同一触发源在短期内不重复触发，并限制单位时间内的触发次数。

- **FR-023**: 系统 MUST 支持禁止打断的情形（剧情演出、玩家正在说话、NPC 正在施法、界面弹窗），在这些情形下 MUST 不发起自主行为。

- **FR-024**: 系统 MUST 按统一优先级仲裁多个候选行为，优先级从高到低 MUST 至少覆盖：危险自保、战斗战术、玩家指令、剧情事件、关系事件、日常自主行为。

- **FR-025**: 系统 MUST NOT 输出无法执行的行为；当目标、条件或资源不满足时，MUST 返回明确的不可执行说明而非虚构行为。

- **FR-026**: 系统 MUST 支持玩家以文本与语音两种方式下达指令，语音在转写后 MUST 进入与文本一致的后续处理。

- **FR-027**: 系统 MUST 将玩家自然语言解析为受白名单约束的语义意图，且解析 MUST 在规则与模型两种方式间可切换并在失败时自动降级。

- **FR-028**: 系统 MUST 在解析无法确定意图时请求澄清，MUST NOT 猜测执行。

- **FR-029**: 系统 MUST 结合当前世界状态、NPC 自身状态与关系阶段决定最终行为，并保证同一意图在不同情境下可产生不同结果。

- **FR-030**: 系统 MUST NOT 使用当前不可用的能力，也 MUST NOT 以目录外的能力替代玩家的指定目标。

- **FR-031**: 系统 MUST 为每次决策产出可解释的原因说明。

- **FR-032**: 系统 MUST 处理客户端上报的世界事件（含战斗与生活两类），并返回 NPC 的反应与可选建议。

- **FR-033**: 系统 MUST 对事件处理实施幂等，同一事件标识重复上报时 MUST 回放首次结果且不产生新行为。

- **FR-034**: 系统 MUST 仅依据世界状态边沿变化触发反应，MUST NOT 依赖逐帧上报。

- **FR-035**: 系统 MUST 以统一注册表描述 NPC 的全部可用能力，涵盖战斗行为、生活行为与信息查询三类。

- **FR-036**: 系统 MUST 允许为回答设定类与状态类问题而查证权威信息源，且查证 MUST 为只读。

- **FR-037**: 查证失败或无结果时，系统 MUST 明确表示不确定，MUST NOT 编造事实。

- **FR-038**: 查证 MUST 有轮次与时间上限，超限后 MUST 降级为直接回应。

- **FR-039**: 系统 MUST NOT 直接改变游戏世界状态；一切改变 MUST 以受约束的指令形式交由客户端执行，客户端 MUST 保有最终否决权。

- **FR-040**: 系统下发的指令 MUST 只引用本次交互上下文中已存在的标识，越界 MUST 被拒绝。

- **FR-041**: 系统 MUST 在任一子系统（模型、语音、记忆、关系、查证、配置）故障时保持可用并降级，MUST NOT 阻塞客户端的游戏主流程。

- **FR-042**: 系统 MUST 记录每次交互的来源与版本信息，用于观测与归因，且 MUST NOT 将交互数据自动用于训练。

- **FR-043**: 系统 MUST NOT 在输出中泄露内部实现细节（路径、资产名、坐标、函数名、凭据）。

- **FR-044**: 系统 MUST 支持面向多个 NPC 的路由与状态隔离，且未登记角色 MUST 被拒绝而不回退至默认角色。

- **FR-045**: 系统 MUST 采用**单一指令体系**：所有下发指令使用同一信封并按行为类型区分；实现层按活动场景分文件组织，MUST NOT 建立平行的多套指令体系。
