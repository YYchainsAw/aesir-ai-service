# AI 能力部署分工与原计划对照

> 版本：`placement-v1`；日期：2026-10-21。依据用户确认的 15 项能力分配，对照服务器工作区 `e4e20f7` 及已有未提交六步开发方案整理。本文记录未来部署目标与原计划覆盖程度，不表示能力已经实现、端到端通过或正式上线。

本项目在服务器通过 PyCharm 远程开发；代码的开发位置与发行后的运行位置分别判断。Boss 冻结策略运行在玩家电脑，队友的语义、对话和长期状态服务运行在服务器，UE 保留世界状态、即时控制和实际执行权。API 版本、字段及当前支持项仍以[现有契约](../protocols/npc-contract-v0.3.md)为准，不能仅依据本表添加未支持字段。

本表与 UE 仓库 `Docs/02_Design_Doc/TDD/06_Deployment.md` 使用相同的 `placement-v1`、`AI-DEP-01`～`AI-DEP-15`。跨仓文档采用各自仓库内路径定位；正式发布或验收时另记录两仓的确切提交、服务版本与游戏构建。部署顺序见[六步开发方案](local-boss-cloud-companion-roadmap.md)；排期与完成状态仍只由 [GitHub Issues](https://github.com/YYchainsAw/aesir-ai-service/issues) 维护，本文的“已有／部分／补充”仅判断原文档覆盖。

## 跨端最小规则

### 分清高层建议和即时执行

Python 原有移动、自主行为和战术解析能力继续保留：它可提出“跟随谁”“等待什么条件”“用哪个已获准能力”。UE 持续控制路径、站位、朝向、实时目标和攻击时机。云端建议与正在执行的本地行为发生冲突时，按现有指令优先级、忙碌状态和可打断规则处理，不新增远程强制打断通道。

### 断网、过期与恢复

Boss 推理、敌人 BT、队友基础本地行为和 GAS 结算应在公网断开时继续工作；云端对话与新自然语言指令可以明确暂不可用。已经合法登记的条件指令只在原有效期/遭遇内由 UE 校验，服务晚到回包不能复活过期指令。恢复时先核对玩家/存档/本次游玩与服务版本，不直接重演积压战术响应。

长期状态的“服务器保存、本地缓存”是目标位置，缓存字段、版本与失效规则尚未实现。离线关系增长、离线事件重试、读档和冲突合并需第二至四步具体设计；不承诺把客户端最终数值直接覆盖服务端，也不借本次方案新增通用跨设备同步系统。

### ASR、VAD 和语音播放

当前真实转写仅支持 Python 进程所在机器的 `faster_whisper`；第一步远程开发指南记录的开发配置为 `mock`，实际启用后端须随运行版本核对。外部 ASR 是目标方案，尚无适配实现。VAD 仅确定在采用时位于本地，是否纳入首期、流式上传及参数继续由 EXT-07 收口。TTS 不在本次新增实现范围；“音频播放在本地”也不表示已经有语音生成服务。

### 版本、身份和证据

多人前必须把可信玩家身份、存档与 NPC 作用域贯穿存储、缓存、限流、去重和回执。历史仅按 `game + npc` 分区的实现不能直接代表玩家隔离。开发服务仅回环监听、通过 SSH 转发联调，正式入口、认证与数据库按后续阶段实施。

Boss 发行清单至少关联模型身份、Schema/动作映射、运行时版本和 SHA；获取/更新失败不得影响已验证版本或本地 BT。自动下载、热替换、签名分发并非本次已实现内容。日志默认内容、外部模型外发和保留仍依据实际代码与配置说明，不能通过文档宣称已经脱敏或只留摘要。
