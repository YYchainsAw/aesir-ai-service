# 质量与验收计划

## 当前缺陷与交付缺口

下表区分代码缺口、环境阻塞与待验，避免把“没部署”误认为“没有实现”。排序按当前交付价值，不是虚构已知线上事故。

| 优先级 | 类型 | 当前问题 | 完成条件 |
| --- | --- | --- | --- |
| 高 | 跨端闭环 | directive 到 UE 实际启动/命中/完成、wait/follow/技能目录逐项对应还缺完整证据 | 同一关联链中保留输入、快照、合法指令、UE 实际行为及真实回执；不能伪造 executed |
| 高 | 环境阻塞 | 当前可用真实 LLM 凭据未重新验证；历史出现 InvalidSubscription | 恢复可用后端，区分 llm/fallback，完成真实文本/指令测试 |
| 高 | 材料阻塞 | 冻结 Boss ZIP/selection/training manifest 和本机 sb3-contrib 缺失 | 原产物可信到位后验证真实启动/推理；新训练仍按用户要求暂停 |
| 高 | 待验 | ASR 已有本机真实样例，但目标服务器、UE 麦克风、文本兜底与真实 LLM 整链路未验完 | 记录模型/设备/录音格式、识别结果、后续回复、错误兜底与耗时 |
| 高 | 数据策略 | 默认信号可保留完整对话；自动保留/脱敏/按用户删除范围未闭合 | 明确保留与删除目标，再实现和验证；清记忆不等于清关系或日志 |
| 中高 | 恢复接入 | SQL 服务端已有实现，但 UE 缓存/离线队列、重启/读档冲突和历史回执恢复未闭合 | 断网、重启、换局、清记忆后均不重放过期指令、不复活旧数据 |
| 中高 | 发布验收 | systemd/Nginx 仍是模板；正式数据切换、OS 权限、HTTPS、备份调度/回滚和容量未全部实证 | 在独立固定发布副本验收，不直接以开发进程当生产 |
| 中 | 协议功能 | 完整 started/hit/completed 阶段、未来条件监听等仍未交付 | 明确协议与 UE 实现，保持当前 accepted/executed 边界 |
| 中 | 质量证据 | 自主行为多样性、记忆/纠错、人物风格及真实输入到实际表现的时延仍需正式采样 | 对应指标、场景和样本，而非仅 HTTP 成功率 |
| 中 | 配置体验 | 裸默认 redis + json 被安全门禁拒绝，新手需要显式开发配置 | 使用导览中的 memory + json；未来可设计明确开发/生产 profile，不能移除门禁 |
| 中 | CI/平台待验 | 新 job 已配置但尚未推送执行；本机 Windows 会跳过部分 POSIX 与真实库测试 | 远端 Linux CI 及专用 MySQL 环境补证据 |
| 后置 | 未实现 | TTS、VAD、播放打断、Boss 自动分发/可信更新及完整 Windows 包 | 各自立项/实现/实机验证，不能把配置模板当成已交付 |

对话 RL 仅保留信号与离线评估工作，没有上线在线学习或人格自演化。它不应优先于当前文本、指令、语音和可靠性闭环。
