## 1. 本步目标与边界

当前按角色或游戏/角色工作的记忆、关系、会话、心跳、事件和调试状态，不能代表共享服务的玩家隔离。第二步使这些状态有一致的归属，并明确何时允许处理、重复请求如何处理、旧游玩与晚到结果何时失效。

| 本步交付 | 本步不承担 |
| --- | --- |
| 可信主体解析边界、存档归属校验及可注入的开发测试身份 | 商业账号、OAuth平台、正式令牌签发、公网开放和费用配额 |
| 新版请求/响应模型、作用域、显式运行生命周期和兼容门控 | 改写所有旧协议为同一个版本，或改变 Boss Schema 4 |
| 单 worker JSON 长期状态分区，进程内状态分区及记忆重置屏障 | MySQL部署/迁移、多 worker、分布式事务与永久恰好一次保证 |
| 相对时间预算、有限窗口的请求/事件去重、回执归属校验 | 完整动作阶段状态机、离线批量补传、跨设备同步和冲突合并 |
| 服务端自动回归、golden样例与UE对接清单 | UE连接、PIE/Shipping实际执行、真实LLM/ASR质量或端到端性能验收 |

第二步继续使用 Python 3.12、FastAPI/Uvicorn、Pydantic v2、标准库 UUID/单调时钟/锁及 pytest/TestClient。新增领域模型与存储访问边界，不为身份字段引入额外服务。第四步再评估 SQLAlchemy、PyMySQL、Alembic 与受支持 MySQL LTS；服务器现有 5.7.43 不直接作为新正式服务的选型，既有数据库实例和其他业务不在本轮变更范围。

## 2. 已批准业务决策

| 编号 | 建议采用的规则 | 影响与后续边界 |
| --- | --- | --- |
| DEC-SCOPE-01 | 同一 `save_id` 的长期记忆/关系跨死亡重试保留；重试只替换 `run_id` 并清单局状态 | 与完整持久存档/检查点不同。未来分支读档按新的存档归属或世代隔离，不用新run冒充长期状态回滚；UE尚无完整SaveGame，本步不实现它 |
| DEC-SCOPE-02 | 首期每个游戏/玩家/存档只允许一个当前活动run；新run通过显式控制替换 | 简化旧回包隔离；跨设备同档并行游玩不在首期范围。服务重启后显式重新绑定，不凭普通业务请求恢复活动资格 |
| DEC-SCOPE-03 | 新队友云端契约采用v0.4；旧版只在显式开启的开发兼容模式进入独立legacy作用域 | 缺身份的请求不进入新版玩家数据；严格模式阻断未接新版的旁路。Boss版本不受影响 |

以上三项已于2026-10-21由用户审查通过，后续实现以本页与契约为依据。已有[时间与跨存档问题#57](https://github.com/YYchainsAw/aesir-ai-service/issues/57)保留；本步只收口身份、生命周期和时效契约，不以本步完成替代其快进时间、记忆衰减等全部历史范围。

记忆清理沿用既有业务范围：清指定归属的记忆和对话会话，保留关系、人格及历史回执/信号。草案新增的epoch屏障用于阻止重置前的结果回写，不借此扩大删除范围。

## 3. 改动入口与依赖顺序

先形成统一作用域与模型，再贯穿有玩家状态的调用链；数据分区、运行缓存、时效可按接口准备，最终通过兼容入口和集成回归收口。人格包、能力目录和世界观仍按游戏/角色共享，Provider级连接池/熔断不机械复制到每位玩家。

| 工作包 | 源码/资料入口 | 完成后的可观察结果 | 前置 |
| --- | --- | --- | --- |
| DEP2-01 作用域与新版边界 | `app/schemas/`、可信主体/存档归属解析边界、新版契约与golden | 请求先解析同一不可变上下文；拒绝缺失、冲突、未登记或不安全ID；客户端世界对象ID不充当认证身份 | 用户审查本计划及契约 |
| DEP2-02 长期状态与重置屏障 | `memory/store.py`、`relationship/state.py`、`companion/session_memory.py`、`dialogue_service.py`、console清理链 | 双玩家/双存档隔离；同档重进恢复；会话不截断碰撞；重置前生成任务不能恢复已清记忆；旧JSON保持原位 | DEP2-01 |
| DEP2-03 运行状态、日志与回执归属 | `api/v1/agent.py`、`agency/throttle.py`、`tactical/event_policy.py`、`console/runtime_state.py`、回执与信号存储 | 心跳、自主抑制、最近观测和输出分区一致；跨角色/存档不能查询、重置或关联回执 | DEP2-01 |
| DEP2-04 显式生命周期与时间预算 | run/encounter控制边界、`world_context.py`、`directives/common.py`、业务入口与生成返回边界 | 替换/结束run或encounter后拒绝实时建议；排队/生成时间计入预算；服务重启后旧绑定无效 | DEP2-01；与DEP2-02的epoch规则对齐 |
| DEP2-05 请求/事件幂等与关联 | 请求协调器、事件共享评估、响应缓存及回执关联 | 同载荷重试复用结果/指令ID；冲突拒绝；并发只做一次副作用；回放不延长TTL；窗口/容量/重启边界可见 | DEP2-01/02/03/04 |

## 4. 服务端验收矩阵

以下定义验收，不代表已经运行。所有用例均核对返回值与状态前后对照，使用可注入时钟/身份和临时存储；不调用付费模型或要求UE连接。

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| AT-SCOPE-01 | 缺失/伪造玩家、跨归属存档、非法路径ID、游戏与角色不符 | 在副作用前拒绝；不回退匿名共享角色，不写入其他归属 |
| AT-SCOPE-02 | 两玩家同角色、同玩家两存档、跨角色同会话ID | 长期文件与短期缓存均隔离，关系/心跳/自主抑制不串扰 |
| AT-SCOPE-03 | 同档新run、返回/重试、竞争激活和旧控制请求 | 只有显式当前绑定可生效；旧业务请求/激活重放不能重新激活已结束run |
| AT-SCOPE-04 | 同档重进、存储重新加载、旧无归属JSON | 按DEC-SCOPE-01保留长期状态；旧JSON不自动归属或被覆盖 |
| AT-SCOPE-05 | 记忆重置与生成返回/并发写入竞争 | epoch核对与提交在同一作用域保护下完成；重置前结果不复活记忆；关系/人格/其他归属不受清理影响 |
| AT-SCOPE-06 | UTC偏差、快照过旧、排队超时、生成完成已过期 | 单调耗时与已用预算生效；过期不发布可执行建议，响应原因可定位 |
| AT-SCOPE-07 | 同ID同载荷、不同载荷、并发重复及跨作用域同ID | 首次结果和指令ID稳定；冲突拒绝；窗口内副作用不重复；跨作用域不相互命中 |
| AT-SCOPE-08 | 同事件跨world/combat重复、回执跨归属、缓存容量/重启 | 规范化事实键一致；回执只能关联原归属；不静默扩大窗口或承诺跨重启恰好一次 |
| AT-SCOPE-09 | 缓存回放、旧run/遭遇、重置后的请求重放 | TTL不重新开始；旧实时建议拒绝；epoch不成为绕过去重、重复施加关系副作用的新键 |
| AT-SCOPE-10 | 严格/legacy模式及对话/流式/语音/事件/回执/console入口矩阵 | 每个入口明确支持新版或拒绝；legacy只写独立旧空间，不能读写新玩家归属 |
| AT-SCOPE-11 | 服务进程重启与显式重新绑定 | 已落盘长期状态/epoch按约定恢复；旧实例绑定被拒绝；丢失的内存去重不包装成持久幂等保证 |
| AT-SCOPE-12 | 本轮回归、契约样例和文档状态 | 各任务单测及适用核心回归有真实结果；golden对应明确版本；不把计划、Mock或服务端通过写成UE通过 |

## 5. 与后续阶段的交接

UE后续需要保存/提供逻辑归属、显式切换run/encounter、取消旧请求并复核回调身份、用本地单调时钟扣除有效期、在Action/GAS启动前再校验。当前阶段只交付对接清单和服务端模拟客户端结果，不修改UE或测试连接。

第四步负责可信凭据与存档登记的正式实现、跨重启去重持久化、数据库迁移和备份恢复；第三步负责实际建议→执行→阶段回执闭环。第二步的回执归属/去重不等于已实现动作完成状态机。离线队列、服务端事务与冲突合并依照AI-DEP-10另行验收，第二步不接收离线批量补传或客户端关系数值覆盖。

Boss推理、KI-01/KI-06、ONNX/NNE和Windows发行仍在第五步/UE主线，不合入本里程碑。
