# 第三步：队友开发闭环实施计划

> 2026-10-22，`loop-plan-v1`。用户授权继续第三步；服务器基线 `main@e96151b`，开发分支 `feature/npc-execution-loop`。本轮交付第三步的服务端部分，UE修改、连接与实际动作验收仍后置；不据服务端通过宣称第三步整体验收完成。

六步与EVO映射以[主方案](local-boss-cloud-companion-roadmap.md#六步与演进批次的对应)为准。本步复用第二步v0.4的可信开发主体、作用域、显式绑定、epoch、单调预算和有限窗口幂等，新增协议在[闭环增量契约](../protocols/npc-loop-contract-v0.4.md)维护。日常任务状态由GitHub维护，不复制完成勾选。里程碑为[DEP3](https://github.com/YYchainsAw/aesir-ai-service/milestone/7)，工作包对应[#76](https://github.com/YYchainsAw/aesir-ai-service/issues/76)～[#80](https://github.com/YYchainsAw/aesir-ai-service/issues/80)。服务端实现与回归范围见[验证记录](../logs/verification-records.md#loop-20261022)，操作与UE交接见[开发指南](../guides/scoped-development.md#loop-usage)。

## 1. 本轮目标与边界

| 交付 | 边界 |
| --- | --- |
| 同会话chat/agent文本FIFO、有限等待与全局生成并发 | 规则心跳不进生成队列；取消不等于撤销已提交事实，不承诺强制中断同步HTTP中的供应商 |
| 明确逻辑请求的排队、运行、取消及终态；新增取消/状态查询 | 保留request_id语义，网络重试仍复用原ID；没有永久结果存储或跨重启恰好一次 |
| 剩余预算约束上游调用、取消/旧绑定后不再生成下一轮或写入迟到结果 | 同步HTTP超时仍受传输实现限制，返回后继续按单调预算检查；真实LLM费用和延迟另验 |
| 已发布指令→既有回执枚举→不倒退的最小执行反馈账本 | accepted仅收到，executed仅UE自报执行；不新增started/hit/completed，不推断命中、伤害或实际完成 |
| 修复已有跟随/等待与战术能力的服务端映射、查询及测试链 | 只使用现有动作/技能目录；未支持的条件等待明确无动作/澄清，不伪造UE本地监听 |
| 完整样例、隔离测试和UE接入清单 | 不修改UE，不测试UE连接，不调用付费LLM或安装真实ASR/RL依赖 |

正式账号、事务数据库、跨重启幂等及离线补拉在第四步。scoped SSE/语音、外部ASR、VAD/TTS/播放打断仍按已采纳的后续批次实施。本轮单worker、JSON与内存后端，不公开开发实例。

## 3. 服务端验收

| 编号 | 场景与通过条件 |
| --- | --- |
| AT-LOOP-01 | 同会话并发文本有序，后一轮读取前一轮已提交历史；跨会话在全局限额内并发 |
| AT-LOOP-02 | 排队/生成期间取消、取消先于业务到达，旧结果不追加完整对话/记忆/关系或发布指令；已开始最终提交时返回取消未生效，不回滚已有事实 |
| AT-LOOP-03 | 队列/并发/状态容量有界，排队计入原预算；心跳/事件与取消控制不加入长对话生成队列 |
| AT-LOOP-04 | 上游调用以剩余预算收紧timeout；取消/过期与供应商故障分开，不能被fallback或熔断吞掉后继续调用 |
| AT-LOOP-05 | 请求同ID重试不重生成；改session/epoch/binding或载荷不能绕过去重；查询不泄露其他归属 |
| AT-LOOP-06 | 同一指令重复回执不重复追加；同sequence异内容冲突、终态不可倒退，批内错误在追加前拒绝 |
| AT-LOOP-07 | 回执写入不确定时订单标unknown；换新HTTP请求ID也不能自动重做；进程退出边界如实报告 |
| AT-LOOP-08 | 文本跟随/等待与可用战术能力产生可关联建议；未支持条件或非法目标明确无动作，不扩大获准目录 |
| AT-LOOP-09 | 状态查询只报告已知请求/指令及实际阶段耗时，无数据时返回unknown ID错误；状态查询不重新下发动作或续期 |
| AT-LOOP-10 | 新模型/golden与适用核心回归有版本/命令；不将TestClient、mock transport、回执自报写成UE执行或真实LLM通过 |

## 4. UE后续验收

UE需保存原request_id、首次发送单调时间、scope/binding/epoch/encounter；显式替代意图先取消原请求，并使原回调本地失效。服务回复后再次检查当前场景、目标、目录、距离、资源、冷却、动作锁和有效期，按实际情况回报既有结果。接受、开始、命中和完成需要后续双方确认协议，不能压成同一个success。

本轮接口/状态不代替UE执行去重、条件登记与监听、技能真实激活、断网兜底或SC-011端到端采样。待这些证据齐全后才判第三步整体验收。
