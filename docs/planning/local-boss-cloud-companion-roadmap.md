## 分工与运行位置

| 部分 | 开发与运行位置 | 职责与边界 |
| --- | --- | --- |
| Python 开发工作区 | 服务器 `/www/wwwroot/aesir-ai-service`，PyCharm 远程解释器 | 修改与验证 NPC 服务及共享协议；使用独立 Python 3.12+ 环境；开发进程可按需启用 reload |
| 队友云端服务 | 开发期在服务器调试；正式版使用独立固定发布副本 | 对话、语义理解、记忆与关系、结构化建议及回执采集；LLM 可调用外部 Provider；UE 复核并执行 |
| Boss 冻结策略 | UE 玩家设备的独立本地推理进程 | 首期保留 localhost HTTP；本地完成高层决策，GAS/UE 负责实际动作与结算；云端不可用不应阻断 Boss 战斗 |
| 正式发布实例 | 后续独立发布目录，例如 `/www/wwwroot/aesir-ai-service-releases/<release>/` | 固定提交、独立环境配置/venv/端口/数据；不得直接跟随 PyCharm 正在编辑的工作区 |
| 训练与可选计算 | 独立用途环境与受控资源 | RL 训练不进入 NPC 请求链路；语音模型和训练依赖按阶段安装，不作为核心 API 启动前提 |

先完成远程环境与契约；队友云端闭环和 Boss 本地发行可并行，并与 UE 现有 M1 完整流程开发并行。多人内测前完成持久化、身份访问控制与发布隔离。

## 第一步：建立可复现的远程开发环境

- 使用 Python 3.12+ 和项目独立 venv，核对 PyCharm 远程解释器、项目根目录与运行工作目录；不替换系统 Python。
- 按用途安装依赖：先 `requirements.txt` 核心服务及项目本身；运行现有测试时另装 `requirements-dev.txt`。真实 ASR 才安装 `requirements-ml.txt`，RL 训练/本地 Boss 运行使用独立环境与 `requirements-rl.txt`。
- 记录启动、健康检查、规则/mock 后端与测试入口。区分已有测试的通过、跳过、缺可选依赖和未执行部分，保留提交与解释器版本。
- 密钥与运行数据不入 Git；开发期先使用本机监听与 SSH 转发完成 UE 联调。生产域名、公开访问及进程守护在第六步验收。

验收：服务器终端能以项目解释器启动 NPC 服务并运行适用的现有测试；UE 可访问健康检查与规则/mock 请求。Python 测试通过不能代替 UE 联调；尚未执行的 UE 检查明确标为待验。操作和本轮证据见[远程开发指南](../guides/remote-development.md)。

## 第二步：明确接口身份、作用域与有效期

2026-10-21 本步细化为[实施计划](step-02-identity-scope-plan.md)与[v0.4契约草案](../protocols/npc-scope-contract-v0.4-draft.md)，已于2026-10-21经用户审查通过，进入 `feature/npc-scope-v04` 分支实现；现有v0.3与新版入口分别验收。

- 区分可信玩家身份、存档、一次游玩/对话会话、遭遇、世界快照、请求、指令和回执的标识及生命周期。玩家身份在开放多人前与认证主体绑定，不能仅相信客户端自报。
- 记忆和关系归属采用 `game + player + save + npc`；会话、遭遇用于短期状态和时效，不能代替存档身份。读档、重新进入与服务重启后的保留/重置规则写入契约。
- 存储路径、进程缓存、心跳限流、事件/请求去重和回执关联均采用相应完整作用域。声明请求时间、快照年龄和指令有效期；跨 UE/Python 同步 schema、契约与 golden 样例。

验收：两个玩家使用同一 NPC 时记忆、关系和限流互不影响；同玩家不同存档隔离，同档重进按约定恢复。旧数据归属不明确时单独处理，不自动并入任意玩家。

## 第三步：跑通队友云端完整闭环

- 首期选少量文本对话、跟随/等待和已有战术能力，沿当前可执行目录逐项打通，不先扩展技能范围。`agent/step` 处理语义与建议，纯心跳走规则，避免每次心跳调用 LLM。
- 云端输出结构化建议与必要条件，包括目标、来源、请求/快照关联和有效期。需要等待条件的指令由 UE 本地监听条件并重新校验；逐帧战斗控制不等待云端往返。
- UE 校验场景、目标、距离、冷却、资源、动作锁与时效后执行；回执区分实际收到、启动、完成、拒绝或失败等阶段。具体字段先对齐现有契约，HTTP 200/202 不表示完成。
- 对齐 UE 与云端总超时预算，限制 LLM 并发；网络重试复用同一请求 ID，重复请求不得重复产生记忆/关系副作用或动作。晚到/乱序响应按有效期与当前上下文处理，上游故障走明确降级。

验收：文本输入到云端语义、UE 实际执行及阶段回执可沿同一关联链追踪；断网、上游超时、重复提交、目标失效和过期响应不导致重复动作或陈旧指令误执行。真实端到端时延另行采样，不以 HTTP 单点耗时代替。

## 第四步：补持久化与访问控制，再开放多人

- 开发阶段先明确身份和存储访问边界，首期保持单 worker 与按归属隔离的 JSON；不通过增加 worker 掩盖进程缓存/文件一致性问题。
- 多人内测前评估受支持 MySQL LTS 的独立应用库与最小权限账号，持久化记忆、关系、请求去重及回执；内容可继续使用 JSON 字段，暂不引入 Redis、MQ 或向量数据库。服务器现有版本实测为5.7.43，既有实例和其他业务不在第二步变更范围，新正式服务不直接沿用旧版本作为选型。
- 通过存储访问边界迁移，明确旧 JSON 归属、备份、导入校验、切换和回滚；迁移失败不能静默丢失已有数据。多 worker 待跨进程一致性另行验证后评估。
- 补充请求鉴权、玩家/存档访问授权、请求与费用配额、音频上传限制；调试查看/重置接口与业务接口隔离。

验收：跨玩家读取/修改被拒绝；服务重启后按约定恢复；重复请求及回执保持幂等；备份恢复与 JSON 迁移可核对且可回滚。完成该阶段前不宣称具备正式多人服务能力。

## 第五步：并行完成 Boss 本地发行

- 保持现有独立 localhost HTTP 推理方案，冻结 Schema 4、26 维观测、9 动作契约；短期不为切换引擎内推理重写现有链路。
- 交付冻结模型、运行时、schema/动作映射与版本清单、模型 SHA；模型不随 Git clone 自动到位，运行时须识别正确候选。
- UE 管理本地推理进程的启动、就绪检测和退出；修复并复测 UE 已知问题 KI-01/KI-06 所涉回退与生命周期问题。异常时使用本地 BT，具体行为以 UE 契约为准。
- Windows 运行时与可执行发行包在 Windows 原生环境构建和验证；Linux 开发服务器保存源码或模型不等于已产出可用 Windows 包。

验收：断开公网时 Boss 推理与 BT 回退仍可运行；首次启动、未就绪、进程异常、退出和模型不匹配均有可复现结果。先完成该验收，再评估 ONNX/NNE，不把其作为首期前置条件。

## 第六步：建立独立正式发布入口

- 正式实例从固定提交/发布版本创建独立副本，环境配置、venv、端口和持久数据与开发实例隔离；发布进程不启用 reload，使用进程守护与明确重启策略。
- 配置 Nginx HTTPS 反向代理、健康检查、日志轮转、备份与回滚；仓库源码和密钥不作为静态网站内容提供。流式对话代理保持正确转发行为。
- 用真实 UE 调用频率、小规模并发和完整请求路径压测；分别记录规则、LLM 和可选语音指标，再决定容量，不直接承诺玩家人数。
- 正式 API 与 RL 训练进行资源隔离或错峰；本机训练占用不能算作可供在线服务使用的余量。

验收：线上版本可追溯且不受开发编辑影响；发布失败可回退；进程故障、备份恢复和健康检查可验证；并发与超时结论有对应环境和 UE 实测证据。

## 首期范围与后续边界

首期采用文本优先、小规模验证、外部 LLM、单 worker 的队友云端服务，并并行交付本地 Boss。ASR 质量与吞吐、语音合成、ONNX/NNE、多 worker/水平扩容和复杂自动部署按后续明确需求安排；人格在线学习/自演化仍未获立项。本文没有修改既有技能数量、FR/UC 数字或 SC 验收结论。

历史 SDD 的单机/本地文件及不含公网部署、多用户、数据库的界限仍作为旧基线保留。本次用户明确批准的是本文所述云部署、玩家隔离和数据库演进方案；后续具体业务变更仍需同步相应需求/规则/验收与契约。方案获准与代码、数据库、发布和 UE 验收完成分别记录。
