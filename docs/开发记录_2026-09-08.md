## 变更内容

### 1. 规则解析器多意图冲突顺序（retreat priority 90 早于 hold 判断）

- `app/services/parsers/rule.py`：判断链改为按 order `priority` 降序——
  撤退 90 > 条件施法 80 > 保留 60 > 优先普攻 50 > 跟随 40。
- 修复场景：「别放爆裂魔法，快撤退保命」此前命中 hold（60），现正确产出 retreat（90）。
- 回归测试：`test_rule_parser_intent_conflict_resolved_by_priority`。
- v0.1 golden 输入无冲突，既有测试全部不受影响。

### 2. order 内部模型 `extra="forbid"`

- `app/schemas/tactical_order.py`：`ContextAgent`/`ParseCommandContext`/`TargetRef`/
  `WhenStateEntered`/五个 then 动作/`ExpiresEnd`/`_OrderBase`/`TacticalAcknowledgement`
  全部补 `model_config = ConfigDict(extra="forbid")`。
- 传入未声明字段现在抛 `ValidationError` 而非静默忽略，与顶层
  `ParseCommandResponse` 的严格校验理念对齐。
- 回归测试：`test_order_internal_models_reject_extra_fields`。

### 3. companion YAML 损坏返回 503 而非 500

- `app/main.py`：注册 `CompanionProfileError` 全局异常处理器，统一返回 503
  `{"detail": "Companion profile is unavailable: ..."}`。
- 覆盖 chat / parse（companion_reply 生成）/ tactical resolve（acknowledgement）
  所有读取 YAML 的路径；UE 侧可区分「配置故障」与「未知异常」。
- 回归测试：`test_corrupt_profile_yaml_returns_503_not_500`
  （坏 YAML → 503；注意构造默认路径在 import 时绑定，测试须替换
  `CompanionProfileRepository.__init__` 指向坏文件）。
