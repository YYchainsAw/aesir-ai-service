# 远程部署、隔离与同步

> 2026-10-21用户采纳的目标方案，2026-10-22提交时按`main@4e2badc`对齐已合并v0.4子集。本页定义完整开发/发布要求；本次未执行部署、迁移、真实ASR或并发验收。新版字段以[v0.4契约](../protocols/npc-scope-contract-v0.4-draft.md)为准，旧[v0.3](../protocols/npc-contract-v0.3.md)及其引用的v0.1/v0.2仅用于显式legacy开发兼容，不将完整DEP目标当已实现API。

已采纳的轮次取消、语音播放、事件治理、记忆来源和请求幂等等增量见[交互演进计划](../planning/npc-interaction-evolution.md)。该计划引用本页DEP规则，新增AT-EVO与现有AT-DEP按场景互相补充；TTS/VAD/流式转写与打断后置实施，不改变本页首期按键录音和外部ASR分工。字段/供应商/预算启用前另行对齐，原模型分发与训练隔离目标保持。

## 范围与权威位置

Boss冻结推理和BT、队友实时控制及所有实际世界执行在玩家本机；远程NPC服务负责语言理解、人格对话、查证、记忆/关系和高层建议，转接外部LLM/ASR。多个独立单机客户端可以共用一个游戏的服务实例；一进程一游戏约束保留，多玩家不等于单进程多游戏或多人联机战斗。

| 需求 | 目标 | 实现边界 |
| --- | --- | --- |
| DEP-REQ-01 | Boss本地、NPC远程HTTPS，开发继续支持本机联调 | UE位置和本地进程交付在UE仓 `Docs/02_Design_Doc/TDD/06_Deployment.md` 维护（跨仓位置）；正式发布/验收另记录两仓确切提交 |
| DEP-REQ-02 | 已认证玩家及存档隔离 | 覆盖全部入口、持久数据、缓存、限流、日志查询、回执与删除，不只改目录 |
| DEP-REQ-03 | 服务权威持久化与UE缓存同步 | 真实事实有持久去重、版本和确认，支持重启、冲突及重置屏障 |
| DEP-REQ-04 | NPC服务转接外部ASR，保留文本兜底 | 当前mock/faster_whisper用于开发；外部适配及数据流待实现 |
| DEP-REQ-05 | 初始Boss模型随包，服务端提供版本清单和可选更新 | 来源可验证、兼容检查、安全阶段切换和回滚；不在战斗中更新权重 |
| DEP-REQ-06 | 独立运行环境、持久存储、进程守护和资源控制 | 在线服务与训练分开调度；开发reload不用于正式服务 |
| DEP-REQ-07 | 断网/超时不阻塞本地战斗与游戏出口 | 旧建议不补执行，离线状态如实显示，恢复有退避和边界 |
| DEP-REQ-08 | 分路径可观测、可复现的容量与费用验收 | 记录身份作用域及关联ID，敏感数据脱敏；历史本机样例不代替远程验收 |

## 身份、存储与同步规则

下表是规则的唯一完整维护位置；SDD、UE和联调页引用编号。玩家/存档、绑定和memory_epoch已有v0.4字段；第四步已新增受控SQL事务、确认版本与事实/回执恢复，见[持久化契约](../protocols/npc-persistence-contract-v0.4.md)；UE缓存/队列及完整生产恢复仍待验。后续精确字段、错误码和版本继续同步schema、契约及golden，不向legacy v0.3混填。

| ID | 规则与最小保证 |
| --- | --- |
| BR-DEP-01 | 认证主体由服务签发或可信身份系统确认；先验证存档归属，再绑定玩家、游戏、存档、角色和会话，遭遇/请求另保留生命周期。所有存储、缓存、节流、去重、回执和查询使用该作用域。请求自报player_id、party.player或companion_id不能充当认证。凭据可过期/撤销，供应商密钥不下发；旧未授权接口仅开发可用。 |
| BR-DEP-02 | 服务端事务数据库是记忆、关系、确认版本和同步去重的权威存储；复用数据库资源须按[六步方案](../planning/local-boss-cloud-companion-roadmap.md)第四步评估受支持MySQL LTS，使用独立应用库与最小权限账号。现有实测5.7.43不直接作为新正式服务选型，不原地升级或改动现有业务实例；具体新版号、表结构及迁移按后续实现设计核定。当前进程字典+线程锁+JSON只能保留为隔离开发后端或迁移输入，不能据此启用公网共享服务或多worker。多worker前完成跨进程一致性；Redis等仅按缓存/节流需要引入，不增加无必要MQ或独立人格微服务。 |
| BR-DEP-03 | UE缓存按玩家/游戏/存档/角色分区并标注版本；离线只追加带稳定事件ID、来源、原遭遇和存档世代的真实事实/回执。服务以持久唯一键去重，在事务中确认应用结果及版本，客户端收到确认后再移出待同步队列。丢失确认重发、重启和乱序不能重复计分。发生版本冲突时拉取权威快照，只重试仍合法且未确认的事实，不上传整个本地关系值覆盖服务。历史事实可按原归属归档，但不得生成当前世界新动作。 |
| BR-DEP-04 | 游戏实时状态与动作最终由UE决定；断网时本地基础AI和仍有效的已接受条件指令继续，云端聊天/新增语言指令明确不可用。恢复时仅上传合法事实/回执和新鲜快照，不补发旧心跳、历史聊天、音频或过期命令。队列有配置容量、保留期限和失败状态；达到上限不静默丢失后宣称同步成功，退出不等待云端。 |
| BR-DEP-05 | 录音、按键说话和播放在本地；UE通过已认证HTTPS入口上传必要音频，NPC服务调用外部ASR并将转写送入同一角色/上下文校验。上传大小/时长/格式/并发和超时在接入前配置并校验；空转写、噪声、依赖失败给可恢复提示和文本入口，不猜执行或自动重传历史音频。外部厂商、允许外发、保留/删除策略发布前明确；未经声明不切换本地Whisper或其他供应商。 |
| BR-DEP-06 | 记忆清理仍只清指定作用域的会话/长期记忆，保留人格/关系及既有日志范围；服务记录新的记忆重置世代/屏障，撤销旧记忆缓存和旧世代记忆写入资格，客户端旧队列不得恢复已清内容。混合事实按记忆/关系分别确认处理结果，不清除已确认关系或用新事件ID重复计分。账号/存档切换先隔离会话；分支读档使用独立世代，旧事件不得借当前身份重放。多设备同时写入由服务版本控制收敛，不承诺任意跨设备存档合并。 |
| BR-DEP-07 | Boss版本清单与模型产物由可信发布者发布，校验签名/来源、SHA-256、协议/Schema、输入/动作映射和游戏/推理运行时兼容性；哈希不替代来源验证。下载校验后只在菜单或新遭遇前原子切换，失败保留已验证版本或本地BT；保留回滚产物。正式实验固定模型/配置，不接受在线学习或战斗中换权重。 |

## 首期服务器部署

以下按[六步与EVO对应](../planning/local-boss-cloud-companion-roadmap.md#六步与演进批次的对应)应用于本次发布已启用的范围：语音/ASR、音频门禁和流式代理要求在启用对应入口时验收，后置VAD/TTS/播放打断不作为文本首版发布前置条件。scoped SSE/语音未实现时仍拒绝，不通过legacy旁路开放。

以下是本轮研究时的历史快照，不作为当前服务器状态；随后环境及v0.4开发进展见[远程开发指南](remote-development.md)和[scoped交接](scoped-development.md)。2026-10-21只读核对的目标主机为Ubuntu22.04、4vCPU、约8GB内存、无计算GPU；当时约3.8GiB内存和58GB磁盘可用，已有网站、数据库和训练进程。这是时点资源快照，不是并发保证。系统默认Python3.10低于项目声明的3.12+；代码位于`/www/wwwroot/aesir-ai-service`，当时无项目虚拟环境、运行配置和模型，NPC端口未监听。后续部署记录重新核对实际环境，不沿用快照数字当运行证据。

1. 先完成BR-DEP-01/02及现有公开入口的作用域保护，准备事务数据库迁移、备份恢复和受限数据目录；旧JSON按明确玩家/存档归属导入，归属不明的数据不得自动并入公共角色。
2. 使用独立Linux Python3.12+环境，安装核心运行依赖。生产NPC无需Boss的Torch/SB3或本机Whisper依赖；配置外部LLM、ASR和服务器凭据。以下仅为环境准备参考，不代表当前代码可直接公网发布：

```bash
cd /www/wwwroot/aesir-ai-service
python3.12 -m venv .venv
.venv/bin/python -m pip install -e .
.venv/bin/python -m pip install -r requirements.txt
```

3. 使用systemd或现有宝塔进程守护，以受限服务用户运行，不开`--reload`，首期一个worker。NPC内部仍可监听`127.0.0.1:8011`，由Nginx提供外部HTTPS入口；玩家访问服务器域名而非回环地址。运行数据/密钥在静态站点根之外，禁止把整个仓库或数据目录作为静态站点公开。
4. 对外只开放完成认证和配额的业务路由。`console/*`、调试UI、文档和记忆管理入口分开授权或保持管理网络可达，不能沿用当前无认证调试接口。健康检查只暴露必要状态，避免泄露路径、配置和其他玩家数据；已有SSE保持流式转发。
5. 配置连接/请求/上传限制、玩家和上游费用配额、取消/超时、重试退避及日志轮转。当前UE文本5秒、心跳2.5秒与上游LLM15秒的预算不一致，发布前按完整链路协调并实测，不能只调大客户端超时。ASR单列预算，规则指令不因长对话/语音排队失去响应。
6. 在线服务与RL训练分开调度；限制CPU、内存、队列及上游并发。先各单worker验证，扩容前完成共享状态和数据库连接一致性检查。监测进程重启、健康、超时/错误、队列、磁盘/内存与费用；备份恢复覆盖业务数据、确认版本、重置屏障和去重记录。
7. 保存部署代码/数据库迁移/配置版本、依赖锁定、证书、外部后端、数据范围和回滚步骤。正式域名、服务账号、具体ASR厂商、音频上限、保留期限、并发配额和完整超时预算在发布记录填实；这些值不是本次凭空确定的业务数字。

服务先提供随包模型的同版本清单和可信产物获取位置，再实现可选更新；模型不由Git克隆自动分发。服务端发布步骤不启动Boss训练，详细模型材料以[RL说明](../../rl/README.md)为准，客户端交付、回滚及推理语义只在UE部署说明维护。

## 外发、离线与恢复

外部LLM接收生成所需文本、人格约束、检索记忆和适用上下文；外部ASR接收必要音频和识别配置。玩家凭据、其他玩家数据及不必要的世界快照不转给供应商。当前实际日志会保留完整文本，事实说明仍见[数据流](llm-integration.md)，本次不将其写成已经脱敏或只保留摘要。发布前确定最小字段、日志访问、保留和删除范围；记忆reset不等于删除供应商或全部日志。

断网时Boss、本地基础队友行为和退出流程继续。仅ASR失败且NPC仍可达时可改文本；NPC整体不可达时明确提示云端语言能力不可用，只保留本地已实现的直接操作，不假称文本也能完成云端解析。LLM单独故障可走服务已有规则降级，但不保证任意表达都能执行。已接受条件指令只在原遭遇与有效期内本地执行。重连先认证、校验归属和重置世代，再取得权威版本、同步真实事实、提交新鲜快照；旧响应和待执行建议不得恢复。身份失效时暂停云端写入，不回退到匿名共享存档。

## 验收条件

以下`AT-DEP-*`对应DEP-REQ与BR-DEP，完整远程/UE/生产验收尚未完成，不作为原AT-01～12或SC已通过。第四步服务端受控子集与AT-PERSIST实测另见[验证记录](../logs/verification-records.md#persist-20261022)，不能据其通过关闭完整AT-DEP。

| ID | 场景 | 通过条件 |
| --- | --- | --- |
| AT-DEP-01 | 正式HTTPS入口、错误/过期/撤销凭据、调试路由和静态路径探测 | 未授权请求拒绝；业务认证可用；仓库/数据/供应商密钥及管理接口不公开 |
| AT-DEP-02 | 至少两名玩家使用相同游戏/NPC及同名存档，跨归属查询/写入/重置 | 对方数据不可见不可改；同玩家不同存档独立；身份由服务验证而非自报 |
| AT-DEP-03 | 两名玩家同时心跳、指令和语音；一人超频/耗尽配额 | 节流、缓存、记忆、关系、回执和费用按正确作用域计算，不以共享NPC ID误伤另一玩家 |
| AT-DEP-04 | 同事件重复/乱序、确认丢失、客户端及服务重启后重传 | 原事实最多计分一次，确认及权威版本可恢复；不制造新的UE动作 |
| AT-DEP-05 | 双客户端版本冲突、分支读档、旧遭遇事实与队列达到上限 | 不用陈旧分数覆盖权威值；新旧存档世代隔离；未同步如实显示，队列有边界 |
| AT-DEP-06 | 离线积压→清记忆→重启→重连上传旧队列 | 清理范围正确，旧记忆不复活；人格/关系及日志按既有范围保留 |
| AT-DEP-07 | 真实外部ASR正常/空白/噪声/错格式/超限/超时及供应商故障 | 音频门禁和预算生效；转写进入当前角色/目录校验，失败能用文本且无猜测执行；mock不代替真人样本 |
| AT-DEP-08 | 启动离线、战斗中断网、条件指令触发、终局/重试后迟到回包 | 本地Boss/基础队友及游戏出口可用；不执行过期/旧局建议，重连不重播聊天/音频 |
| AT-DEP-09 | 错签名/哈希/Schema/运行时、下载中断、不兼容构建、更新回滚 | 只启用可信兼容模型；保留旧模型/BT；战斗中版本不变，原始模型可追溯 |
| AT-DEP-10 | 1/5/10独立客户端档位、长对话和语音混合、训练隔离及服务重启 | 记录P95/P99、超时/错误、费用/资源和回退；满足已记录预算的档位才可作发布容量，多worker另验状态一致 |
| AT-DEP-11 | 旧v0.1/v0.2/v0.3请求绕过新入口，伪造存档/游戏/角色、重复执行反馈 | 无作用域旧入口不公网开放；兼容请求也完整鉴权；新字段/版本有schema和golden样例，不绕过执行去重 |
| AT-DEP-12 | 数据库迁移失败、备份恢复、权限撤销及供应商切换 | 有可执行回滚；业务版本、去重和重置屏障一致恢复；旧凭据无效，数据外发范围与实际配置一致 |

时延分开报告网络往返、服务排队/处理、外部ASR、LLM首字/完整回复和UE首次实际表现。原NFR-02/SC-011本机样例保留原范围，远程测试按已记录预算及失败样本验收，不自动放宽或宣称达标。UE检查入口见其`DEP-UE-*`；每次真实运行记录提交、配置、并发和原始证据，再更新验证记录。

## 当前实现差距

v0.4已实现可信开发身份、存档授权、玩家/存档/角色分区、显式绑定、相对时效、持久memory_epoch和有界内存幂等；旧入口默认关闭并保留独立legacy命名空间，详见[scoped交接](scoped-development.md)。第四步服务端已实现独立SQL事务/持久去重、服务端Bearer/存档授权、原子事实确认及历史回执归档，并有实际MySQL/进程重启/空库恢复证据，见[开发指南](persistent-development.md)。当前开发`.env`保留JSON模式，没有自动迁移/切换现有数据或公开服务。UE凭据/缓存/离线队列、正式HTTPS/OS隔离、完整灾备收敛、外部ASR、scoped SSE/语音、模型发布/签名下载与生产容量仍待验；所有后端继续单worker，不支持可靠共享多worker。现有服务端回归不替代本页AT-DEP完整远程验收。实现与跨仓依赖统一追踪[todo](../planning/todo.md)，本页不复制任务勾选或伪造运行记录。
